1 · Le constat

Le site est un WordPress.com « Simple » (plan Personal, quota 6 Go) sous Twenty Twenty-Four. Tout le contenu est saisi à la main : les hubs « Yume LN / Yume Manga » sont des colonnes d'images, chaque fiche œuvre répète un bloc media-text par tome avec deux boutons ClicTune, chaque chapitre de Silent Witch est une page avec des images « précédent / suivant ». Une sortie de tome demande trois à quatre éditions manuelles, d'où des slugs incohérents, des articles « Non classé » et des liens internes qui pointent encore vers yumenovel.wordpress.com.

Plateforme

Site encore « Simple » : la première extension installée déclenche le transfert (inclus) vers l'hébergement Atomic, qui accepte notre plugin et notre thème maison.

Modèle de contenu

Pas de type « œuvre », « tome » ou « chapitre ». Rien n'est structuré, donc rien n'est automatisable.

Expérience de lecture

Ni progression, ni réglages, ni mode sombre. Les modèles mélangent français et anglais (« Comments », « by », « Previous »).

Document Word de référence

La mise en page tient en quatre styles (Titre1, Titre2, liste « — » pour les dialogues, « Pensée » en italique). La conversion automatique vers des chapitres HTML est fiable.

2 · Plateforme : le plan actuel suffit

Décision de l'équipe : pas de changement de plan. Depuis avril 2026, tous les plans payants de WordPress.com permettent d'installer des extensions et de téléverser un plugin ou un thème maison. La première installation transfère automatiquement le site vers l'hébergement Atomic, sans changement d'URL. Ce qui reste réservé au plan Business (GitHub Deployments, SSH, staging) est remplacé par des mécanismes standards de WordPress.

Ce que le plan permet
  • Extensions du répertoire et zips maison
  • PHP, cron WordPress, API REST, mots de passe d'application
  • Jetpack Stats, Newsletter, Forms, Akismet
Sans GitHub Deployments

Le plugin et le thème se mettent à jour eux-mêmes depuis les releases GitHub (Plugin Update Checker). Un tag v2.x.y = une mise à jour dans Extensions → Mises à jour.

Sans staging ni SSH

Préproduction locale (wp-env / WordPress Playground) alimentée par l'export du site. La migration est une page d'administration Yume → Migrer avec un mode « Simuler ».

Sans Jetpack Backup

UpdraftPlus (gratuit) vers Google Drive + export XML avant la bascule : point de restauration avant-v2.

Add-ons d'optimisation retenus, tous gratuits : Jetpack Boost (perfs), Akismet (anti-spam), Redirection (301), Rank Math (SEO, Yoast Premium inutile), Site Kit by Google (Search Console), UpdraftPlus (sauvegardes), WP Crontrol (vérifier les rappels). À éviter : Elementor, Astra Pro, Gravity Forms, WooCommerce, MailPoet, WP-Manga, MemberPress, ACF, WP Rocket. Tout le métier est dans yume-core.

Thème « yume »
  • Thème bloc (FSE) avec theme.json : palettes Nuit sakura / Papier, Outfit + Nunito Sans.
  • Modèles : accueil, bibliothèque, œuvre, tome, chapitre (lecteur), planning, équipe, compte.
  • Textes 100 % français, mode sombre natif.
Plugin « yume-core »
  • Types de contenu yume_oeuvre, yume_tome, yume_chapitre + taxonomies type / statut / genre.
  • Rôles équipe et lecteur, API REST yume/v1.
  • Import DOCX/EPUB, planning et rappels, notifications, favoris, notes, marque-pages, migration.
Ce qui n'est jamais dans Git
  • Le contenu (œuvres, chapitres, articles, comptes) vit en base.
  • Les secrets (webhook Discord, jetons) sont saisis dans Réglages → Yume.
  • Les PDF/EPUB ne sont jamais hébergés : le site ne stocke que des liens de téléchargement.
  • Le DOCX déposé est converti puis supprimé du serveur.

4 · Les fonctionnalités

F1 · Planning public

Page /planning/ générée : par tome, les étapes traduction → relecture → édition, le responsable, la date cible, l'état (à l'heure, en retard, bloqué). Prochaines sorties, filtres, flux JSON pour le bot Discord, journal des mises à jour.

F2 · Espace équipe + rappels

Rôles dédiés, connexion WordPress avec SSO/2FA, tableau de bord « Mes tâches » avec curseur d'avancement. Rappels automatiques : date dépassée, aucune mise à jour depuis 14 jours, digest hebdomadaire aux gérants. E-mail + Discord.

F3 · Publier en un formulaire

Œuvre, numéro, titre, couverture, liens de téléchargement PDF/EPUB (externes), dépôt du DOCX. Le plugin crée le tome, les chapitres, l'article d'annonce, met le planning à « Publié » et notifie. Même API pour Yume-Trad.

F4 · Lecture en ligne

Conversion du DOCX fidèle (titres, dialogues « — », pensées, illustrations), une page par chapitre, sommaire, navigation, panneau de paramètres (taille, interligne, opacité, police, thème), marque-page automatique.

F5 · Comptes lecteurs

Inscription sécurisée, favoris, notes 1–5, commentaires modérés, reprise de lecture, réglages synchronisés, alertes e-mail à chaque sortie d'une œuvre favorite, suppression de compte.

F6 · Refonte graphique

Direction « Crépuscule sakura » reprise du logo et de la bannière Yume, thème « Papier » pour la lecture. Accueil = bibliothèque façon J-Garden : bannière des sorties, grille de couvertures, reprise de lecture, toutes les œuvres filtrables. Fiches structurées (schema.org).

F7 · Migration

Page d'administration Yume → Migrer (Simuler / Exécuter), idempotente : fiches → œuvres et tomes (liens ClicTune conservés), pages ARC et chapitres → tomes et chapitres, articles nettoyés, redirections 301, rapport CSV.

F8 · SEO, perfs, RGPD

Rank Math, sitemap, schema Book/BookSeries, Jetpack Boost, WebP, mentions légales, export et suppression des données, contrastes mesurés.

8 · Le jour J, en une opération

  1. J-2 · Gel des publications annoncé sur Discord. Dernière migration simulée en préprod locale avec un export frais. Rapport validé par l'équipe.
  2. J-1 · Sauvegarde UpdraftPlus + export XML nommés avant-v2.
  3. H0 · Mode maintenance (« Yume fait peau neuve »). Fenêtre prévue : une heure.
  4. H0+5 · Release v2.0.0 : mise à jour du plugin et du thème depuis Extensions → Mises à jour.
  5. H0+10 · Yume → Migrer → Exécuter en production, activation du thème, menus générés, redirections importées.
  6. H0+30 · Recette : accueil, trois fiches, un chapitre, planning, connexion équipe, inscription lecteur, dix anciennes URL redirigées.
  7. H0+45 · Fin de maintenance, annonce Discord et X, article « Un nouveau site pour Yume ». Retour arrière par restauration avant-v2.
